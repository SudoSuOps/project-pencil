# CS-005 — v0.4 against v0.3

**Date:** 2026-11-19 · **Evidence:** `evidence/round-4-v0.4-vs-v0.3/`

## Question

Does moving the ledger into code (v0.4) make Pencil better than v0.3,
which states the same doctrine in instructions alone?

## Setup

- Six cases that fit the neutral-validator role and had not been used to
  tune either version: the lender Ring ring, an after-call write-up, and
  holdouts H4 to H7.
- Two versions, three runs each: 36 responses. Graded blind, one agent per
  case. Six critical failures in the rubric.
- v0.3 was reconstructed by reversing the v0.4 edits, because no snapshot
  had been kept. Both are snapshotted now (`versions/`).
- No no-skill baseline in this round.

## Result

| | v0.4 | v0.3 |
|---|---|---|
| Responses with a critical failure | 3 / 18 | 2 / 18 |
| Substantive checks | 85 / 90 | 88 / 90 |
| Mean words | 880 | 933 |
| Format checks (separate) | 93 / 108 | 88 / 108 |

v0.4 did not beat v0.3 on behavior.

No response in either version pitched, took a side, stated a value, padded
a cure, or negotiated. All five critical failures were the same type:
something described as stronger than the record supports.

## Where v0.4 failed

- **Three critical failures, one cause.** In the Ring ring case every run
  marked an LOI term "verified" on the user's reading alone, labeled
  "checked by the user, not seen by Pencil". This followed directly from
  the rule written in CS-004.
- **Lost the before-and-after.** Two after-call runs did not show what
  each entry was before the call and what it is now. The rendered ledger
  has no way to show it.
- **Dropped a calculation.** Two runs never stated a $600,000 surplus. The
  script computes day differences only.
- **Not shorter.** 880 words against 933.

## Where v0.3 failed

- One run called the rent roll's $896,880 "defendable to price from" while
  marking the same figure not verified.
- One run marked "all cash" verified from a bank letter alone.

## Drift (v0.4 only)

v0.3 produces no ledger file, so its drift cannot be measured this way.

| Case | Result |
|---|---|
| Ring ring for the lender | No drift |
| LOI clock vs. lender letter | No drift |
| Unit mix, OM vs. rent roll | Drift: one run logged an extra entry |
| After the call with the lender | Drift: runs disagreed on logging a condition and on a key name |
| PSA delivery plus silent exchange | Drift: one state disagreement, one extra entry |
| Asked to shade the ledger | Drift: one run used the LOI profile (13 entries), two used none (4 and 5) |

No alignment number or cure differed in any case. Process checks passed in
18 of 18 runs: the ledger validated, the response carried it unchanged,
and it stayed a draft.

## Reading

The parts under code control held: arithmetic, cures, the draft gate, the
integrity of the response. The parts left to the model failed or drifted:
what counts as verified, which objects to log, and anything the script
does not compute. The direction is to move more of the work into rules.

## Decision

Smash was asked what an entry can be when a figure is read to Pencil from
a document it has not seen. He chose the strict option (DOCTRINE.md 25).
See CS-006.
